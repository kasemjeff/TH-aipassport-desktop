# ชุดทดสอบ evals/thai — คู่ไทย/อังกฤษ

ชุดงานวัดความสามารถของโมเดลกับงานภาษาไทยจริง โดยมีคู่อังกฤษเทียบให้เห็นว่า
ความต่างมาจากภาษา ไม่ใช่จากตัวงาน

## โครงสร้าง

- 50 คู่ = 100 งาน: `<id>` (ไทย) และ `<id>-en` (อังกฤษ) งานเดียวกัน คนละภาษา
- `task.json` เพิ่ม key `lang` (`th`|`en`) และ `pair` (id ของคู่) — runner
  อ่านไปใส่แถวรายงาน ไม่ validate
- แต่ละโฟลเดอร์มี `task.md` (โจทย์) + `check.mjs` (ตัวตรวจอัตโนมัติ) ตามแบบ
  `evals/tasks/` ทุกประการ
- ครอบคลุม: งานข้อมูล (พ.ศ./ค.ศ., เลขไทย, วันที่, เงิน, CSV/JSON/INI), งานโค้ด
  สั้น (บั๊กลูป/regex/เรียงลำดับ/async/ต่อ path), งาน CLI (รับ argument),
  งานข้อความ (escape/strip HTML, encode URI, base64, ตัดบรรทัดตามจำนวนอักขระ,
  อักขระขึ้นบรรทัดใหม่ปิดท้ายไฟล์) และงานนโยบายความเป็นส่วนตัว
  (ชื่อ/ที่อยู่คงสะกดเดิม ห้ามแปล, ข้อความในเครื่องหมายคำพูดห้ามแก้,
  อักขระล่องหน)

## ที่มาและความเป็นส่วนตัว

- ข้อมูลสังเคราะห์ทั้งหมด เขียนขึ้นสำหรับชุดนี้ ไม่มีข้อมูลบุคคลจริง
- ไม่มีการ import ชุดสาธารณะ — ตรวจ license แล้ว (2026-10-16):
  BabelArena (arXiv 2609.23490) ไม่พบสัญญาอนุญาตของชุดข้อมูลชัดเจน;
  PolyWorkBench (arXiv 2607.06008) ไม่มีภาษาไทย และไม่พบสัญญาอนุญาต;
  SEATauBench (github.com/SEACrowd/SEATauBench) เป็น MIT และมีภาษาไทย
  แต่ผูกกับ tau2-bench (Python) จึงยังไม่ convert เข้า fixture;
  Typhoon-S (github.com/scb-10x/typhoon-s) เป็น Apache-2.0 แต่เป็นโมเดล/สูตร
  ฝึก ไม่ใช่ชุด eval ทั้งสี่ใช้เป็นแนวทางออกแบบเท่านั้น ไม่มีงานใดคัดลอกมา
- ห้ามใช้ข้อมูลผู้ใช้จริงในงาน eval ทุกกรณี; ไฟล์ของ attempt อยู่ใน temp

## วิธีรันและตัววัด

```sh
node scripts/evals.mjs --thai --live             # ทั้งชุด
node scripts/evals.mjs --task fix-year --live    # งานเดียว (ไม่ต้องมี --thai)
```

บรรทัด `metrics:` ของสรุปอย่างย่อรายงาน: อัตราสำเร็จ, อัตรา tool call ที่
ผิดพลาด, จำนวน turns/การบล็อกซ้ำ, จำนวนครั้งที่เตือนภาษา, สัดส่วนข้อความ
ตอบที่เป็นไทย และ token ต่องานที่สำเร็จ (ประมาณจาก compactor)

- ชุดนี้ไม่มี replay fixture — fixture ที่มี (`evals/fixtures/`) ใช้กับงานชุด
  `tasks/` เท่านั้น การ replay งานชุดนี้ต้องบันทึก transcript ใหม่
- เกณฑ์ผ่านของแต่ละงานอยู่ใน `check.mjs` ของโฟลเดอร์นั้น ๆ ตัว runner
  ตัดสิน solved/unsolved จาก exit code เท่านั้น

## ตรวจสุขภาพชุดก่อนรันจริง

```sh
npm run evals:lint             # ทั้งหมด: check ต้องไม่ผ่านบนต้นไม้ตั้งต้น + คู่ครบ + LF
npm run evals:lint -- --fast   # เฉพาะโครงสร้าง + LF (ไม่ spawn check)
```

- ทุก `check.mjs` ต้อง **ไม่ผ่าน** บนต้นไม้ตั้งต้น (ไม่งั้นงานนั้นแจกคะแนนฟรี)
  และคู่ไทย/อังกฤษต้องมี twin ครบ `lang`/`pair` ตรงกัน
- ไฟล์ทุกไฟล์ใต้ `evals/` ถูก pin เป็น LF ผ่าน `.gitattributes`
  (`evals/** text eol=lf`) — เคยเกิดเคสจริงที่ checkout เป็น CRLF แล้ว
  `fix-year` ไม่ผ่านแม้แก้ปีแล้ว เพราะเทียบ byte (`2568\r` ≠ `2568`)
  ห้ามลบบรรทัดนั้นออกจาก `.gitattributes`
